# Rednote Sync Core 实现契约

状态：**已实现契约**。更新日期：2026-09-14（补充验证与恢复边界；本轮未改 Core 运行代码）。本文记录本地 Core 的行为；产品范围与在线验收状态见仓库 `docs/design/roadmap.md`。

Core 将规范化列表、正文和媒体保存为可恢复的本地资料。运行时为 Node.js 26 / macOS，使用内置 SQLite，无运行依赖。当前发行包只有离线输入适配器。历史实施 Stage 3 是它最初交付时的研发阶段，不对应当前产品阶段三。

重构前的详细规格保留在 [历史快照](history/sync-core-before-2026-09-12.md)，不再用于约束实现结构。

## 1. 使用入口与边界

- CLI 命令、环境要求、安装和退出码见 [README](../README.md)。
- 输入结构和跨字段校验见 [offline-input-v1](offline-input-v1.md)；类型与持久化 decoder 见 [types.ts](../src/types.ts)。文档不复制完整类型定义。
- `fixture` 和 `import-json` 读取同一规范化 envelope。它们不猜测任意第三方 JSON 的字段。
- Core 不读取浏览器会话，也不发出平台请求。未来采集器可以实现 `SyncSource` 接口；接口存在不表示真实登录、搜索或下载已经可用。

```text
CLI / 调用方
    │
    ▼
SyncEngine ── SyncSource（列表、详情、重试、媒体流）
    │
    ├─ 先保存列表检查点与待处理任务
    ├─ 事务外取得正文、媒体和不可变对象
    └─ 每帖短事务：合并内容、任务、失败与尝试来源
                │
                ▼
         SQLite + objects/sha256
                │
                ▼
       exportAccount / repair-views
       Markdown、JSON、媒体、索引和日志
```

## 2. 身份和任务

`accountId`、scope 和归档分区始终表示**关系所属账号**。输入可另带 `listCollector` 与 `contentCollector`；两者可以与 owner 不同，但平台必须一致。身份只是来源记录，不包含凭据。

例如：主号 A 的点赞列表由 A 导出，内容由 B 采集，失败项随后由 A 重试。归档始终属于 A；任务保留列表采集身份，`attempts` 依次保留 B 的失败和 A 的结果。运行日志记录该次输入声明的采集身份，并用 `listAttempts` 保留每次列表请求的来源和结果。未知身份为 `null`，不将旧输入中缺省的身份猜成 owner。

任务按 owner、平台、目标、可选收藏夹和帖子隔离。正文和媒体可在同一 owner 的不同列表目标之间复用。人工 `skipped` 保持有效；普通失败保留并可独立重试。任务尝试历史记录来源、时间、结果和失败类别，不等同于保存每次原始平台响应。

旧 v1 输入、任务和数据库仍可读取；新增来源字段是可选扩展。本轮不需要数据库 schema 迁移，也没有修改用户真实数据。

## 3. 列表进度与失败隔离

`sync` 在一次打开输入后连续处理可用页面，直到服务端结束、追到已有前沿、输入没有后续页，或遇到需要停止的条件。库调用 `runPage` 仍提供单页入口。离线默认间隔为 0；调用方可以显式设置页间准入间隔和条目间隔。

列表一旦合法接收，就在一个短事务中保存帖子任务和响应 cursor。内容是否完成不再决定列表检查点能否前进。cursor 只来自列表响应；相同或缺失的后续 cursor、重复 cursor 循环会停止为协议问题。

每帖独立处理和提交：

| 情况 | 行为 |
|---|---|
| 单帖详情或暂时网络失败 | 保存该帖失败，继续后续帖子 |
| 部分媒体失败 | 保存正文和成功媒体，任务标为 `partial` |
| 认证、限流、协议异常 | 保存停止原因；不自动换账号或继续请求 |
| 本地状态或对象完整性异常 | 返回相应错误，保留先前已提交结果 |
| 暂停或中断 | 保留列表检查点、已完成帖子和已取得的可保存内容 |

再次 `sync` 先处理上次留下的 `pending` / `paused` 任务，再处理列表；`retry-failures` 只处理未完成任务，不拉取列表。`sync` 中再次列出的已完成帖子可接收新的正文观察，成功媒体按稳定媒体标识复用。同一运行内同一帖子只处理一次。

暂停是停止继续采集，不撤销已提交内容。导出中断只让派生文件暂时不完整；后续导出或 `repair-views` 从事实源恢复。

## 4. 更新语义

正文、标签、指标和作者信息按最近的完整采集快照更新。采集时间来自输入，导入旧文件的当前时间不能冒充新的采集观察。

- 排序键始终是实际采集时间 `observedAt`；只有缺少采集时间的旧 rank 才回退到 `revisionAt`。来源版本保留作溯源，不根据比较对象临时更换时间域。
- `observedAt` 绑定输入的 `capturedAt`，不能在重放时改成当前时间。旧记录从原有正文的 `capturedAt` 补读。
- 相同采集时间却有不同内容，或没有可比较时间时保留已有正文；不以内容 SHA-256 的大小决定谁更新。相同内容的旧重放也不能降低已有观察时间。
- 标签取被选中正文快照的完整集合，所以删除标签能够生效。
- 指标允许数值下降和变成 0。每个输入字段均为显式快照字段；新快照中的 `null` 表示此次未知，按原样保存，不把过去的数值拼接成当前观察。
- 昵称按账号 `lastSeenAt` 选择完整观察，包括 `null`，不再取字典序最大值或拼接过去的名称。
- `capturedAt` 表示目前接收的最新采集观察时间。离线输入必须如实保留该时间；较晚采集到的旧平台内容仍属于较新的观察，Core 不推断平台缓存的新旧。媒体和关系观察单独合并。

媒体按种类和序号组成槽位。新版本的成功对象替换旧对象；失败不会销毁已有成功媒体。只有明确完整的新媒体集合才能将不再出现的槽位标为删除。旧输入晚导入不能凭 hash 大小删除新媒体。

这些规则由 [merge.ts](../src/merge.ts) 与 [rank.ts](../src/rank.ts) 实现，回归覆盖正文更新、标签删除、指标下降、旧观察重放和媒体补缺。

## 5. 内容保真与输入边界

正文里的普通网址、查询参数、长校验码和媒体内部的文本字节可以保留。Core 不再把“像 token 的长字符串”当作凭据，也不把图片或视频整体解码成文本做猜测。

明确的凭据字段、已经在内存 registry 登记的秘密值和测试 canary 仍禁止持久化。媒体按字节分块检查已登记值，跨块值也可检出。这项保护不能识别未登记、伪装在普通正文里的任意秘密；调用方负责在凭据边界登记值，不应把登录会话放进导入文件。

帖子 `publicUrl` 仍由平台适配器校验为规范帖子地址；这和正文中保留普通网址是不同字段的契约。输入及磁盘路径继续检查目录逃逸、符号链接、文件身份和权限。

## 6. 事实源、提交与导出

```text
<root>/state/rednote-sync.sqlite          账号、进度、任务、失败、尝试与清单
<root>/objects/sha256/<prefix>/<sha256>   不可变正文和媒体对象
<root>/accounts/<accountDigest>/         可重建的人类可读导出
```

正文获取、媒体读取与流式哈希、对象和派生文件写入在 SQLite 写事务之外进行。事务内仍会重渲染小型正文产物并检查其摘要。对象先写入并同步，再由逐帖短事务提交引用；事务中检查旧 revision，拒绝悄悄覆盖并发更新。失败或崩溃可能留下未引用对象，但不会提交指向尚未完成对象的清单。

媒体以有界分块读取、哈希和写入，只保留 MIME 检测所需的头部。新增对象在首次写入时计算一次哈希，正常路径不反复读回整文件。已有同 hash 对象复用前仍检查完整性。

`exportAccount` 对已提交快照导出，不持有 SQLite 写事务等待文件 I/O。媒体逐个、逐块复制；已有收据与预期摘要、长度一致且文件基本属性有效时直接保留文件。新帖子不会读取既有媒体或重写其他帖子的正文文件。索引和日志仍在一次导出中汇总一次；它们的处理量随元数据规模增长。

导出每个文件采用临时写入、同步和原子替换。每账号导出锁避免并发覆盖；进程异常退出后的锁可回收。导出结束时核对 canonical generation：采集期间已有新提交，就保留 `views_dirty`，不宣称旧快照已覆盖新事实。

正常导出依赖不可变对象和收据，**不会每次重新检查所有既有文件的字节**。同大小的手工改写可能直到显式 `verify` 才被发现。`verify` 只读地完整检查对象和派生收据；`repair-views` 重建缺失或损坏的派生文件并清理受管理命名空间里的遗留输出。事实源损坏不能通过重建视图修复：丢失的 `objects/sha256` 对象需要有效备份或重新取得原始内容，新建空目录无法恢复内容。

旧 projector/transaction API 仍有薄兼容入口；运行主路径不再采用整页文件撤销机制。旧数据库字段和版本暂时保留，避免为内部简化增加无关的数据迁移。

## 7. 构建与验收

开发依赖由 `package-lock.json` 固定。`tsc --noEmit` 严格检查源码和测试；标准 TypeScript 编译器生成 `dist` 并改写相对模块扩展名。Schema 样例使用 Ajv 2020-12 + formats 检查。运行包不加载这些开发依赖。

工程检查关注类型、编译产物一致性、离线运行边界和分发内容。没有最低源文件数量、固定模块名单或精确 scripts/devDependencies 形状要求。新增模块由编译器发现，不同步多份手写模块清单。

必要检查：

```bash
npm ci --ignore-scripts
npm run build:dist
npm run check
npm test
npm run pack:check
npm run test:offline-demo
npm run test:readme-smoke
```

测试使用临时合成库；真实网站访问、真实账号补缺、媒体播放和用户资料库验收仍是独立产品验证。
