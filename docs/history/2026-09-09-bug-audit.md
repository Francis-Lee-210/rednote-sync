## BUG-001

**两份点赞脚本误接收其他列表响应。**

- 涉及文件：[点赞 Excel](../../prototypes/tampermonkey/xiaohongshu-like-export.user.js)、[点赞 JSON](../../prototypes/tampermonkey/xiaohongshu-like-export-json.user.js)。位置为 `shouldProcessResponse`、`handleResponseText`。
- 触发条件：页面查询参数为 `?tab=liked`；收到非点赞列表响应，例如 `/api/sns/web/v2/note/collect/page`；响应有 `success: true`、`data.notes`，笔记具有脚本要求的字段，但 `interact_info.liked` 为 `false`。
- 原因：兜底分支只要求存在 `liked` 字段，并允许当前点赞 tab 代替逐项点赞判断及响应来源确认。判断通过后，整批笔记进入 `processNotes`。
- 影响：未点赞帖子可能被计入点赞清单，污染后续目标列表及关系归属。
- 证据等级：**离线合成输入复现**。2026-09-09 从两份当前脚本提取实际路由函数，在无网络的 Node VM 中调用；分别预期接收 0 条，实际接收 1 条。明确点赞接口的正向对照均接收 1 条。真实网页是否会产生该响应组合尚未验证。

最小合成响应的关键结构如下，值均为人为构造的测试占位值：

```json
{
  "success": true,
  "data": {
    "notes": [{
      "note_id": "synthetic-note",
      "xsec_token": "synthetic-access-material",
      "user": { "user_id": "synthetic-author" },
      "interact_info": { "liked": false }
    }]
  }
}
```

后续修复验收：两份脚本均拒绝不属于点赞来源的上述响应；明确点赞来源仍可正常收集；覆盖 tab 切换、延迟响应、混合 liked 状态与去重。不能只证明脚本语法有效或导出了文件。

## BUG-002

**收藏脚本滚动按钮选择器错误。**

- 涉及文件：[收藏 Excel 脚本](../../prototypes/tampermonkey/xiaohongshu-collection-export.user.js)，`createUI` 与 `toggleAutoScroll`。
- 结构：容器依次追加计数器、导出按钮、滚动按钮、`poweredBy` 署名元素。
- 原因：`toggleAutoScroll` 使用 `.xhs-button:last-child` 获取滚动按钮，但按钮不是容器的最后一个子元素；按脚本自身 DOM，该选择器无法匹配目标按钮。
- 影响：随后访问按钮的 `textContent` 或 `style` 会失败。开始滚动发生在该属性访问之前，异常也可能使计时器与 `isAutoScrolling` 状态不一致。
- 证据等级：**静态代码确认，未进行浏览器复现**。先前本地浏览器诊断页被浏览器 URL 安全策略阻止，不计作 UI 验收。

后续修复验收：通过稳定的按钮引用或明确标识取得目标；保留署名元素时，连续点击能正确开始、停止、再次开始；按钮文案、状态变量和计时器一致，重复操作不遗留额外计时器。

## BUG-003

**Core README 的包外相对链接阻断打包门禁。**

- 涉及文件：[Core README](../../projects/README.md)、[pack-check.mjs](../../projects/scripts/pack-check.mjs)。
- 触发：在 Core 项目目录运行 `npm run pack:check`。
- 原因：README 含 `../../docs/design/account-identity-model.md` 与 `../../docs/design/roadmap.md` 链接，而打包检查要求 README 的相对链接目标必须属于安装包文件 allowlist。它们在仓库内有效，但不在独立安装包内。
- 证据等级：**命令复现**。2026-09-09 返回退出码 1：

```json
{"ok":false,"error":"PACK_CHECK_FAILED","reason":"README relative link must resolve inside the package"}
```

本次失败发生在预检阶段，没有进入后续 tarball 生成与安装验证。本会话此前的 Core 165 项测试通过不覆盖这条完整打包成功路径，不能代替 `pack:check`。

后续修复验收：同时满足仓库文档导航和独立包内可解析性；保持安装包范围约束，通过 `pack:check` 的真实打包、安装及 CLI 检查。不要为通过检查而整体取消链接或包文件范围校验。
