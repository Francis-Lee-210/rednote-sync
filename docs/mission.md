# Mission：把个人小红书收藏变成可长期使用的本地资料库

状态：**当前权威**
更新日期：2026-08-18

## Why

用户已经通过点赞和收藏筛选了 2000 多条有价值的小红书内容，但平台内搜索、内容失效和信息流干扰使这些内容难以再次找到和认真使用。

Rednote Sync 首先服务用户本人：把这些帖子尽量完整地导出到本地，保留来源和失败信息，并让内容可以长期搜索、整理和再次取用。

## Success looks like

- 能导出用户自己的点赞和收藏列表，并判断扫描是否完整。
- 能按列表获取正文、作者、图片、视频及必要元数据；缺失和失败不会被伪装成成功。
- 重复运行不会无意义地重复保存，任务可以暂停、恢复和检查。
- 原始归档、同步状态、本地整理和 AI 派生结果分开保存。
- Cookie、token、浏览器会话和含访问材料的 URL 不进入 Git 或公开输出。
- 用户不需要重新打开每一篇平台详情页，就能在本地搜索和整理资料。

## Principles

- 个人 MVP 优先于公共产品和商业化。
- 本地资料和可恢复性优先于具体知识库界面或模型供应商。
- 已验证事实、研究推断、产品假设和候选方案必须分开描述。
- 产品提供账号路线和风险提示；具体使用哪种账号形式由用户决定。
- 不把浏览器行为、延迟、账号类型或 Cookie 来源宣传成未经验证的安全保证。
- 当前产品设计以[产品设计](design/product-design.md)为准，当前进度以[路线图](design/roadmap.md)为准。

## Scope

当前范围包括用户自己的点赞和收藏列表、帖子内容与媒体、本地整理，以及未来可能研究的点赞/收藏/收藏夹写回能力。

具体本地整理方式、AI 分类、浏览器采集架构和平台写回实现均尚未确认；它们不能从研究材料中自动升级为产品要求。
