# 分离产品阶段、历史实施阶段与研究材料

状态：**已接受**
日期：2026-08-18

## 决定

- 当前产品设计使用三个产品功能阶段。
- 旧的历史实施 Stage 1–4 保留原意，并与产品阶段分开。
- 当前权威、已实现契约、概念草案、探索、历史、研究证据和学习材料使用不同目录与状态。
- 单项目研究进入 `research/projects/`，跨项目综合进入 `research/topics/`，逆向材料进入 `research/reverse/`。
- 根目录、`docs/` 和 `research/` 使用分层 `AGENTS.md` 约束 Agent 的文档维护行为。

## 原因

旧文档同时使用产品、实施和研究三种阶段语言，导致历史进度被误读为当前产品设计；研究项目和专题也缺乏清晰的目录边界。

## 结果

- 历史内容继续保留，但不能作为当前路线图。
- 研究结论不能自动升级为产品决策。
- 新 Agent 必须先识别文档状态和权威来源，再进行修改。

## 2026-09-19：目录轻整理与单包上移

用户批准保留正式实现、原型、产品文档、研究、学习和私有数据的分类，将原 `projects/rednote-sync-core/` 包根上移到 `projects/`；包名、功能和运行职责不变。产品文档入口统一到 `docs/README.md`，日期化架构审查归入 `docs/history/`，重复学习记录合并到对应课程。根 README 按日常任务导航，研究目录区分当前相关、备用路线和历史证据。

固定来源元数据中的旧路径与哈希保留为历史取证记录；普通文档链接与运行命令使用新路径。本次整理不采用新的采集或知识库架构，不移动真实资料、私有运行材料和第三方源码。
