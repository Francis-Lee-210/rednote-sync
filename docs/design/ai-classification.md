# 小红书本地知识库：AI 内容理解与分类模型选型

日期：2026-08-10

状态：选型建议，待使用真实帖子评测后定稿

## 1. 文档目的

本项目需要对已经导出到本地的小红书帖子进行内容理解，并产生可审计、可修正的多维分类结果。本文件整理两项内容：

1. 不同类型的小红书帖子分别需要哪些模型能力。
2. 豆包 Seed、千问 Qwen、OpenAI GPT 和 Google Gemini 等候选模型的能力与适用范围。

本文件只讨论内容理解、分类、标签生成、聚类和复核，不讨论图片或视频生成。

相关项目背景见：

- [`mission.md`](../mission.md)
- [`product-design.md`](./product-design.md)
- [`ai-classification-pipeline.html`](../../learning/reference/ai-classification-pipeline.html)

## 2. 已确认的项目要求

### 2.1 小红书中不存在真正的“纯文字帖子”

每篇帖子至少有一张图片。区别不在于“是否有图片”，而在于图片承担什么作用：

- 图片只是帖子标题卡。
- 图片是简单配图，主要信息仍在正文。
- 图片本身承载文字信息，例如截图、清单、聊天记录或长图。
- 图片承担主要语义，例如摄影、穿搭、家居、设计或审美内容。
- 帖子是短视频，意义由画面、字幕、口播、音乐和环境声共同构成。

因此，第一步不应把帖子分成“纯文字”和“图文”，而应判断视觉载体在内容表达中的作用。

### 2.2 分类结果是多维分类卡，不是单一文件夹

每篇帖子至少需要支持以下维度：

- `topics`：主题，例如求职、旅行、摄影、饮食。
- `uses`：用途，例如教程、灵感、参考资料、待实践。
- `forms`：表达形式，例如清单、攻略、随笔、访谈、氛围视频。
- `emotions`：情绪或氛围，例如轻松、克制、怀旧、疏离。
- `aesthetics`：视觉或听觉风格，例如低饱和、极简、电影感。
- `entities`：地点、品牌、产品、人物、机构等实体。

分类结果还应保留：

- 支持每项标签的可见或可听证据。
- 不确定性和需要人工复核的原因。
- `unknown` 或 `needs_new_tag`，避免把新兴趣强塞进旧词表。
- `model`、`model_version`、`prompt_version` 和 `taxonomy_version`。
- 原始模型输出与人工修改记录。

模型自己报告的置信度不能作为唯一判断依据。还需要结合证据完整性、相似度、模型间分歧和词表外检测决定是否升级或人工复核。

## 3. 帖子类型与所需模型能力

### 3.1 文字主导：标题卡或简单配图

典型特征：

- 正文已经包含主要信息。
- 首图是标题、封面或与正文弱相关的装饰图片。
- 图片中的文字可能与标题重复。

所需能力：

- 中文正文理解。
- 基础视觉理解，判断图片是否只是封面。
- 简单中文 OCR。
- 多标签分类和严格 JSON 输出。
- 能引用正文中的短证据。

建议内容包：

```text
标题 + 正文 + 原作者标签 + 首图低分辨率版本 + 首图 OCR
```

此类帖子不需要逐张使用高分辨率视觉推理。如果首图 OCR 与标题高度重复，后续分类可以主要依赖正文，但仍应保存图片角色为 `title_card` 或 `decorative`。

适合的默认模型：

- `qwen3.6-flash`
- `doubao-seed-2.0-lite`
- `gpt-5.6-luna`
- `gemini-3.1-flash-lite`

### 3.2 图片文字主导：截图、清单、聊天记录和长图

典型特征：

- 大量重要信息只存在于图片中。
- 正文可能只有一句引导语。
- 图片顺序可能对应步骤或叙事顺序。

所需能力：

- 高质量中文 OCR。
- 小字号、复杂排版和多栏内容理解。
- 多图顺序保持。
- OCR 结果与正文去重、纠错和融合。
- 从图片证据中提取实体、步骤、数字和结论。

建议内容包：

```text
标题 + 正文 + 每张图片 OCR + 图片顺序 + 关键原图
```

适合的模型组合：

- `qwen-vl-ocr` 做文字提取，`qwen3.6-flash` 做融合与分类。
- `doubao-seed-2.0-lite` 直接进行图文理解，并保留独立 OCR 结果用于审计。

不建议只让通用模型“看图后直接分类”，因为后续很难判断错误来自 OCR、内容融合还是分类逻辑。

### 3.3 多图教程、攻略和过程记录

典型特征：

- 图片和正文共同表达步骤。
- 单张图片信息不完整，顺序很重要。
- 可能包含前后对比、操作过程或多个产品。

所需能力：

- 多图片输入。
- 顺序和跨图关系理解。
- 步骤、前置条件、结果和实体提取。
- 长上下文与结构化输出。

适合的默认模型：

- `qwen3.6-flash`
- `doubao-seed-2.0-lite`
- `gemini-3.1-flash-lite`

如果图片数量很多，可以先制作低分辨率联系表供模型做全局判断，再把模型选出的关键图片以原始分辨率补充输入。

### 3.4 视觉主导：摄影、穿搭、家居、设计和审美内容

典型特征：

- 正文无法完整描述收藏价值。
- 色彩、构图、材质、光线、空间和视觉节奏本身就是信息。
- 情绪和美学标签具有较强主观性。

所需能力：

- 细粒度视觉描述。
- 多图风格一致性判断。
- 色彩、构图、材质、场景和风格理解。
- 将“客观可见特征”与“主观审美判断”分开输出。
- 能提供支持美学标签的视觉证据。

建议两层输出：

```json
{
  "neutral_visual_description": "低饱和蓝灰色调，远景人物占画面比例较小",
  "aesthetic_tags": [
    {
      "tag": "疏离",
      "evidence": "单人远景、留白较多、整体低饱和",
      "needs_review": true
    }
  ]
}
```

适合的模型：

- 默认初筛：`qwen3.6-flash` 或 `doubao-seed-2.0-lite`。
- 困难样本：`qwen3.7-plus`、`Seed2.1 Turbo/Pro`、`gpt-5.6-terra` 或 `gemini-3.6-flash`。

此类内容必须使用真实个人收藏做主观评测。通用视觉排行榜不能证明模型理解用户自己的审美语言。

### 3.5 视频主导，但只需判断主题和实体

典型特征：

- 主要问题是“视频讲了什么”。
- 音乐和语气不影响主题标签。
- 可以通过字幕、口播转写和关键帧还原大部分内容。

所需能力：

- 视频时序理解，或“语音转写 + 关键帧”组合处理。
- 字幕和画面文字 OCR。
- 对人物、地点、物品和动作进行实体提取。
- 时间点或关键片段定位。

两条可选路线：

1. 直接视频理解：将视频交给 Qwen、Seed 或 Gemini 多模态模型。
2. 可审计拆解：保存语音转写、字幕和关键帧，再将内容包交给分类模型。

第一版建议默认保留拆解后的证据，即使同时使用直接视频理解。这样模型更换、错误分析和局部重跑都更容易。

### 3.6 音画共同表达：氛围、口播情绪、BGM 和镜头节奏

典型特征：

- 相同字幕在不同语气下表达不同情绪。
- 音乐、环境声或停顿影响用户收藏理由。
- 无对白视频的意义主要来自画面、镜头节奏和声音。

所需能力：

- 视频、音频、图像和文本统一理解。
- 口播语气、停顿、音量和情绪识别。
- BGM、环境声和重要音效识别。
- 音画一致性和时间关系判断。
- 明确承认深层情绪或叙事判断的不确定性。

适合的模型：

- 优先候选：`doubao-seed-2.0-lite`，其官方资料明确说明支持视频、图像、音频和文本的统一理解。
- Qwen 替代路线：使用 Qwen Omni 系列，或使用独立 ASR 加 `qwen3.6-flash`；后者会损失部分语气、音乐和环境声信息。
- Gemini 替代路线：使用支持音频和视频输入的 Flash 系列。

`Seedance` 不适用于这里。它能理解参考素材是为了生成或编辑视频，不是为了稳定地输出忠实分类结果。

### 3.7 待验证思路：先判断内容形态，再分层处理

可以考虑把处理流程拆成两个阶段，而不是将每篇帖子的全部正文、原图和视频直接交给同一个模型。

第一阶段使用一个成本较低的多模态模型，只判断帖子由哪些媒体承担主要信息，以及后续需要调用哪些能力。它不负责生成最终标签，只输出类似下面的路由信息：

```json
{
  "content_profile": "text_led|ocr_led|visual_led|video_led|audio_visual_led",
  "image_role": "title_card|decorative|informational|aesthetic|mixed",
  "text_is_sufficient": false,
  "needs_ocr": true,
  "needs_original_images": false,
  "needs_video_understanding": false,
  "needs_audio_understanding": false,
  "routing_confidence": "high|medium|low"
}
```

第二阶段根据路由结果分发给不同的处理链：

```text
原始帖子
  → 第一层：轻量多模态内容形态判断
      ├─ 文字主导、图片只是标题卡或配图
      │   → 正文 + 必要 OCR → 低成本文本/图文分类模型
      ├─ 图片文字主导
      │   → OCR 模型 → 文本融合与分类模型
      ├─ 视觉或审美主导
      │   → 原始图片 → 较强视觉模型
      ├─ 普通视频主导
      │   → 转写 + 字幕 + 关键帧 → 分类模型
      └─ 音画共同表达
          → 原视频和音频 → 全模态理解模型
```

这一思路可能节省 token 的原因是：多数文字主导帖子不必把所有原图以高分辨率输入昂贵模型，普通视频也不一定需要每次进行完整音画推理。第一层可以只读取正文摘要、首图或低分辨率预览和基础媒体信息，再决定是否加载更昂贵的媒体输入。

这是一个待验证的架构假设，目前不确定：

- 第一层路由本身需要消耗多少 token。
- 路由错误会不会导致重要图片、音频或视频信息被遗漏。
- 哪个模型适合作为第一层路由器。
- 哪些置信度或冲突条件应触发升级和重新路由。
- 相比统一多模态处理，实际能节省多少成本。

为降低错误分发的风险，未来实现时应允许第一层输出 `mixed`、`unknown` 或低置信度，并在这些情况下将帖子交给完整多模态模型或人工复核。本轮只记录该思路，不对模型、阈值和成本收益作结论。

## 4. 候选模型能力对比

以下信息以 2026-08-10 的官方公开资料为准。价格和可用区域可能变化，正式接入前需再次核对控制台。

### 4.2 豆包 Seed

#### Doubao Seed 2.0 Lite

适合本项目的原因：

- 所有小红书帖子都包含视觉内容。
- 能统一理解视频、图像、音频和文本。
- 对视频中的口播情绪、背景音乐、环境声和音画关系更有价值。
- 官方定位是兼顾质量和响应速度的生产级通用模型。
- 当前公开起步价约为人民币 0.6 元/百万输入 token、3.6 元/百万输出 token。

需要验证：

- 对项目 JSON Schema 的严格遵循率。
- 多标签分类中的漏标和过度解释。
- 面对审美维度时能否区分客观特征与主观判断。
- 新西兰环境下火山引擎或 BytePlus 的账号、区域、延迟和媒体上传方式。

#### Seed2.1 Turbo/Pro

Seed2.1 是更新一代的生产力和多模态模型。官方资料强调其视觉、空间、长上下文和长视频理解能力。

在本项目中不建议一开始对全部 2000 条帖子使用 Pro。更合理的用途是：

- 默认模型与标签定义发生冲突的样本。
- 长视频或复杂时序关系。
- 需要更强视觉推理的审美类内容。
- 作为评测阶段的高质量参考模型。

#### Seedance

Seedance 是视频生成和编辑模型。即使它可以理解输入素材，也不应将这种“为生成服务的理解能力”当作分类 API 使用。项目应明确排除：

- Seedance 2.0
- Seedance 2.5
- Seedream 图片生成系列

### 4.3 千问 Qwen

#### Qwen 3.6 Flash

适合成为长期图文分类主力：

- 接收文本、图片和视频。
- 1M token 上下文。
- 支持最长约 2 小时、2 GB 视频。
- 支持多图片和结构化输出。
- 国际区当前 256K 以内标准价格约为 0.25 美元/百万输入 token、1.50 美元/百万输出 token；支持批处理折扣。
- 与 Qwen OCR、Embedding、Rerank 和开放权重生态容易组合。

限制：

- 普通视觉模型对视频音轨的情绪、音乐和环境声利用不如原生全模态路线明确。
- 对高度主观的个人审美标签仍必须做人工评测。

#### Qwen 3.7 Plus

适合作为升级层：

- 官方建议先用它验证质量，再切换 Qwen 3.6 Flash 降低成本。
- 支持文本、图片、视频、1M 上下文和结构化输出。
- 适合长图、多图、复杂视觉关系和困难视频。

#### Qwen VL OCR

适合作为独立提取器，而不是最终分类器。它可以降低“模型因为没看清图片文字而分类错误”的概率，并使 OCR 结果能够单独检查和重跑。

### 4.4 OpenAI GPT

#### GPT-5.6 Luna

适合做低成本图文分类对照：

- 支持文本和图片输入。
- 支持结构化输出。
- 官方定位为成本敏感、高吞吐工作负载。
- 当前标准价格约为 0.20 美元/百万输入 token、1.20 美元/百万输出 token。

限制是不能直接理解完整视频或音频。视频需要使用：

```text
语音转写 + 字幕 + 关键帧 + 原文案
```

再交给 Luna 或 Terra 分类。这个限制也带来一个优点：分类证据天然更容易保存和审计。

#### GPT-5.6 Terra

适合作为 Luna 的困难样本升级层，而不是全量默认模型。视频仍需使用转写和关键帧路线。

### 4.5 Google Gemini

#### Gemini 3.1 Flash-Lite

适合做低成本全模态对照：

- 支持文本、图片、视频和音频输入。
- 支持 JSON Schema 结构化输出。
- 当前标准价格约为 0.25 美元/百万文本、图片、视频输入 token，1.50 美元/百万输出 token；音频输入单价不同。
- Batch 价格通常约为标准价格的一半。

其主要价值是用一个低成本模型直接覆盖图文和视频，作为 Seed 和 Qwen 的独立对照。

#### Gemini 3.6 Flash

适合作为 Gemini 路线中的困难样本升级模型，不建议在评测前用于全部帖子。

## 5. 推荐架构

### 5.1 如果只想先接入一个模型

首轮 MVP 推荐：

```text
Doubao Seed 2.0 Lite
```

原因不是它已被证明在所有分类维度上最好，而是它与真实小红书内容形态最匹配：所有帖子有图片，部分视频还需要同时理解画面、口播、音乐和环境声。

### 5.2 长期推荐：按模态与不确定性路由

```text
标题卡 / 简单配图
  → 正文 + 首图低分辨率 + OCR
  → Qwen 3.6 Flash

截图 / 长图 / 教程
  → Qwen VL OCR + 原图 + 正文
  → Qwen 3.6 Flash

摄影 / 穿搭 / 家居 / 审美
  → 正文 + 原图
  → Qwen 3.6 Flash 或 Seed 2.0 Lite
  → 低置信度时升级到 Qwen 3.7 Plus / Seed2.1

普通短视频
  → 转写 + 字幕 + 关键帧 + 原文案
  → Qwen 3.6 Flash

依赖口播情绪、BGM、环境声和音画关系的视频
  → 原视频 + 原文案
  → Doubao Seed 2.0 Lite
```

这一方案的核心判断是：

- 千问适合作为图文分类、OCR 和结构化数据生成主力。
- 豆包 Seed 2.0 Lite 适合作为音画联合理解专项模型。
- 强模型只处理困难样本。
- Seedance 不进入分类流水线。

### 5.3 保持供应商可替换

所有模型都应通过统一适配层接入，并输出同一份分类 Schema。分类 sidecar 至少记录：

```json
{
  "note_id": "...",
  "content_package_version": "...",
  "provider": "qwen|doubao|openai|google",
  "model": "...",
  "model_snapshot": "...",
  "prompt_version": "...",
  "taxonomy_version": "...",
  "neutral_description": "...",
  "topics": [],
  "uses": [],
  "forms": [],
  "emotions": [],
  "aesthetics": [],
  "entities": [],
  "evidence": [],
  "unknown": false,
  "needs_new_tag": false,
  "needs_review": false,
  "review_reasons": []
}
```

原始归档保持不变，模型结果写入独立的 `derived/classification/{note_id}.json`。

## 6. 评测与最终决策方法

不应根据厂商排行榜直接决定最终模型。建议从真实收藏中抽取至少 80 条：

- 20 条标题卡或简单配图。
- 20 条截图、清单、长图或教程。
- 20 条摄影、穿搭、家居或其他审美内容。
- 20 条视频，其中至少一半依赖声音或氛围。

首轮至少比较：

- `doubao-seed-2.0-lite`
- `qwen3.6-flash`

可增加：

- `gpt-5.6-luna`
- `gemini-3.1-flash-lite`

所有模型必须使用相同的内容包、标签定义、正反例和输出 Schema。评价指标包括：

- 每个分类维度的准确率或 Macro-F1。
- `unknown` / `needs_new_tag` 的召回率。
- 标签证据是否真实存在且足以支持结论。
- JSON Schema 合法率。
- 审美类人工满意度。
- 单帖成本和端到端延迟。
- 进入人工复核队列的比例。

最终应选择“以最低总成本自动通过最多合格帖子，同时不掩盖不确定性”的默认模型，而不是选择通用排行榜最高的模型。

## 7. 当前结论

1. 帖子分类应根据图片角色、内容模态和不确定性路由，而不是根据“美食、旅行、求职”等主题选择不同厂商。
2. 如果只接一个模型快速验证，优先测试 Doubao Seed 2.0 Lite。
3. 长期架构中，Qwen 3.6 Flash 更适合作为大部分图文帖子的默认分类模型。
4. 对音画共同表达的短视频，Doubao Seed 2.0 Lite 比“ASR + 普通视觉模型”更值得优先测试。
5. Qwen 3.7 Plus 或 Seed2.1 Turbo/Pro 只用于困难样本和质量对照。
6. Seedance 是视频生成模型，不用于内容理解和分类。
7. 最终选择必须由真实小红书样本评测决定。
