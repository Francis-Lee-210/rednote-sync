Reference · AI 分类流程

一条帖子怎样变成可筛选标签

状态：学习材料。 本页用于解释历史研究或候选方案，不是当前产品设计；现行状态见产品路线图。

分类不是让模型看标题后猜一个文件夹，而是先把不同模态转换成“内容包”，再产生有证据、可修正的结构化元数据。

1. 原始归档正文、图片、视频、原链接、作者与时间
2. 内容提取语音转写、关键帧、画面文字、原帖文案
3. 中性描述先描述它表达什么，不急着硬分类
4. 多维分类受控词表、置信度、证据、新标签建议
5. 人工筛选按标签浏览，并决定是否进入 Wiki

不同内容进入 AI 前的形态

帖子类型分类输入主要盲点
文字标题、正文、作者标签反讽、隐喻、语境缺失
图文文字 + 原图 + 图中文字/画面描述审美意义常不在正文里
短视频原文案 + 语音转写 + 代表性关键帧 + 字幕无对白、音乐、镜头节奏与叙事关系

建议的输出不是一个标签，而是一张分类卡

{
  "note_id": "...",
  "description": "雨夜街头的慢节奏短片，以旁白讨论离开熟悉城市后的失重感",
  "topics": ["城市生活", "迁移体验"],
  "uses": ["写作素材", "情绪参考"],
  "forms": ["散文式短视频"],
  "aesthetics": {
    "moods": ["疏离", "怀旧"],
    "visual_motifs": ["雨夜", "霓虹", "空镜"],
    "literary_style": ["意象化", "低叙事密度"]
  },
  "entities": ["奥克兰"],
  "evidence": ["旁白提到……", "关键帧显示……"],
  "confidence": 0.74,
  "needs_review": true,
  "suggested_new_tags": []
}
边界：“疏离”“怀旧”是模型基于可见线索给出的描述性判断，不是客观事实。保留证据、置信度和人工修正记录，才能让这种审美分类真正服务于你的个人品味。

数据应放在哪里

raw/notes/{note_id}/...              # 不可修改的事实源
derived/classification/{note_id}.json # 可重跑、可修正的分类卡
taxonomy/taxonomy.yaml               # 你审核过的分类词表
wiki/...                              # 只有你选中的内容才参与编译

新帖子不属于现有类别时

尝试旧词表读取标签定义、别名和正反例
判断未知不强塞；标记低置信度或词表外
进入收件箱保存候选标签和相似未知项
批量审核新增、合并、改名或仍不分类
发布新版本只重跑受到影响的帖子
{
  "taxonomy_version": "1.2",
  "classification_status": "needs_taxonomy_review",
  "matched_tags": [],
  "proposed_tags": ["声音散步"],
  "nearest_known_tags": ["城市漫游", "环境声音"],
  "confidence": 0.38
}

第一版词表只是种子，不是永久边界。详细说明见短课：让分类体系随收藏一起生长。

人工修改怎样影响以后

影响层级系统动作是否自动
当前帖子立即采用用户标签，保留原预测与差异是
相似帖子把修正帖作为检索示例，影响后续相似内容是
全局规则修改标签定义、合并类别或重跑一批旧内容积累一致证据后，由用户批准
原则：每次修正都学习，但单条修正不自动改写全局语义。详细说明见短课：为什么一次修正不等于一条全局规则。

返回短课：AI 分类并不是一次调用。
